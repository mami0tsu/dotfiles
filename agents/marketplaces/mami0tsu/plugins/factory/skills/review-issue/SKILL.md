# Review Issue

## 入力

| 項目 | 内容 |
| --- | --- |
| レビュー対象 | 作成前の Issue の題名と本文、または既存 Issue の本文と追加調査結果 |
| 調査の根拠 | 対象リポジトリや一次情報へのリンク |
| `factory.json` | タスクの成果物の出力先 |

## 出力

| 成果物 | 内容 |
| --- | --- |
| レビュー結果 | 指摘と根拠、または指摘なし |

## 手順

1. レビュー対象と、調査の根拠が示す内容を確認する。
   本文がファイルで渡された場合は、その内容を読む。
1. 背景、対象、実施範囲、リスクが判断できるか確認する。
1. 既存 Issue ではタスクの分割、依存関係、受け入れ条件と出力先について、人間が合意するために必要な情報があるか確認する。
   出力先は設定と照合し、依存関係に矛盾がないか確認する。
   作成前の候補にはタスク構成を必須としない。
1. 記載内容と根拠の食い違い、情報の不足、未確認事項を調べる。
1. 指摘ごとに該当箇所、理由、修正案を返す。
   指摘がない場合はその旨を返す。
