# task-review-design

検証計画の各領域を独立したAgentへ渡し、修正が必要な問題を集める。
作成者の結論や別のAgentのfindingを入力へ混ぜない。

## 入力

- 設計成果物
- 検証計画

## 出力

- Agent検証結果

## 制約

- 検証計画の領域ごとに独立したAgentを使う。
- 各Agentへ入力要求、設計成果物、領域に関係するリポジトリの事実だけを渡す。
- Agentにfile、Git、Issue、Documentを変更させない。
- 必要な領域のAgentを利用できない場合は検証を完了しない。
- 好みだけに基づく指摘を採用しない。

## 手順

### 1. Agentを割り当てる

各領域を検証できるAgentを選び、互いに独立して実行する。

### 2. 結果を集める

各Agentから問題箇所、影響、根拠、必要な修正、再検証方法を受け取る。

### 3. Findingを整理する

同じ根拠と影響を持つfindingを重複排除する。
根拠不足または設計対象外と確認できたfindingだけを除外する。

### 4. 結果を返す

領域ごとの検証状態、採用したfinding、除外したfindingと理由をAgent検証結果として返す。
