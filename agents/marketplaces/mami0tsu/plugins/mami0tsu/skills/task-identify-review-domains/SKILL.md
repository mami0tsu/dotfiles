# task-identify-review-domains

要求整合性を共通領域とし、設計判断と変更対象から追加の専門領域を選ぶ。
Agent数を先に決めず、検証すべき領域から割り当てを作る。

## 入力

- 設計成果物

## 出力

- 検証計画

## 制約

- 要求整合性を必須領域にする。
- 設計成果物とリポジトリの事実から根拠を示せない領域を追加しない。
- 異なる判断を1つの広い領域名へまとめない。
- 検証そのものを実行しない。

## 手順

### 1. 変更対象を分類する

component、データ、interface、security、移行、運用、利用者体験、複数リポジトリの境界を設計成果物から抽出する。

### 2. 領域を選ぶ

要求整合性を追加し、専門知識が必要な変更対象ごとに領域を作る。

### 3. 観点を定める

各領域について、確認する設計判断、関連する事実、期待する検証結果を記述する。

### 4. 計画を返す

領域名、選定根拠、検証観点、Agentへ渡す事実を検証計画として返す。
