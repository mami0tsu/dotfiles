# task-draft-design

確定した要求から、判断根拠と検証方法を追跡できる設計本文を作る。
対象の複雑さに応じて必要な節を選び、根拠のない内容を補わない。

## 入力

- 要求確認結果
- 対象リポジトリごとの調査結果
- 設計作業計画

## 出力

- 設計本文

## 制約

- 未決事項が残っている場合は本文を完成扱いにしない。
- 要求、調査結果、または人間の決定に根拠を持たない判断を追加しない。
- 複数リポジトリに共通する判断と、リポジトリ固有の判断を区別する。
- 実装Issueの分割を本文へ先回りして固定しない。
- 選択した正本で利用できるMarkdownとして作る。

## 手順

### 1. 設計対象を定める

背景、目的、対象範囲、対象外、制約を要求確認結果から整理する。

### 2. 設計判断を書く

採用する構成、データとinterfaceの変更、失敗時の挙動、移行、互換性、運用上の影響のうち、設計対象に存在する項目を記述する。
各判断へ根拠を対応付ける。

### 3. 検証条件を書く

要求ごとに受け入れ条件と確認方法を記述する。
実装完了後に観測できない条件は、検証可能な表現へ戻す。

### 4. リスクを書く

既存機能への影響、移行と復旧、security、運用、未対応領域を設計に関係する範囲で記述する。

### 5. 本文を返す

設計本文と、その本文から除外した未決事項を返す。
