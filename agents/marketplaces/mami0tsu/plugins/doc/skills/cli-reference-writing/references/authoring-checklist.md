# 作成と監査のチェックリスト

## CLI 操作リファレンスの形式

各 CLI 操作リファレンスの先頭に、次の情報を置く。

```markdown
## 情報源

- 公式ドキュメント：<直接 URL>
- 検証バージョン：`<cli> <version>`
- 確認コマンド：`<構文を確認したコマンド>`
```

複数の一次情報を使った場合は、URL と確認コマンドを対応付ける。
確認コマンドには `--version` と、記載した構文を確認した対象サブコマンドを含める。

## 作成時の確認

- [ ] Skill の description に、対象 CLI と利用場面がある。
- [ ] `SKILL.md` に対象ユースケースと参照ファイルへの導線がある。
- [ ] `references/` に少なくとも1つの CLI 操作リファレンスがあり、すべてのユースケースをいずれかの参照ファイルへ対応付けた。
- [ ] すべての CLI 操作リファレンスと `references/validation.md` を `SKILL.md` から直接参照できる。
- [ ] 各 CLI 操作リファレンスに公式ドキュメント、検証バージョン、確認コマンドがある。
- [ ] 各ユースケースに目的、前提条件、推奨コマンド、結果の確認、停止条件、代表的な失敗がある。
- [ ] 公式文書の転載ではなく、対象ユースケースに必要な情報だけを記載した。
- [ ] 入力言語または設定形式が必要な CLI では、ユースケースに必要な最小記法がある。
- [ ] 通常経路ではヘルプを読まず、未収録操作、バージョン差、実行エラーでは対象サブコマンドだけを確認する規則がある。
- [ ] `agents/openai.yaml` の表示名、説明、既定 prompt が `SKILL.md` と一致する。

## 静的確認

repository が提供する Skill または plugin の検証コマンドがあれば実行する。
利用できない場合は、YAML frontmatter、`agents/openai.yaml`、参照リンク、見出し、情報源の URL、コマンドの引用、記録済みバージョンを目視で確認する。
意味上の項目は、上のチェックリストで確認する。

構造検査をスクリプト化する場合も、対象リポジトリで再現できる依存だけを使う。

## Agent シナリオ試験

新しい Agent に Skill のパスと1つの代表ユースケースだけを渡す。
作成者の設計意図、想定コマンド、期待結果は渡さない。

通常経路では、Agent が `--help` を事前に読まず、リファレンスだけで状態確認、操作、結果確認まで進められることを確認する。

未収録の操作、記録と異なるバージョン、構文エラーのいずれか1つを与える。
Agent が CLI 全体ではなく対象サブコマンドのヘルプだけを参照し、リファレンスの対象外または更新が必要な差分を明示することを確認する。

試験ごとに、対象 Skill の `references/validation.md` へ次を残す。

- 実行日と実行環境
- 入力と対象ユースケース
- 読み込んだ参照ファイル
- CLI のバージョンと実行したヘルプコマンド
- 結果と、リファレンスを更新した場合の変更内容

`references/validation.md` は試験記録であり、CLI 操作リファレンスに必要な情報源の形式は適用しない。
失敗した場合は、対象ユースケースの記述またはフォールバック条件を直してから再試験する。
